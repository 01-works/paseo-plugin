# 구현 결정

2026-10-06, 0.1.0. 사용자의 구현 요청과 후속 그래프·ID 복사·시각 구성 요청을 반영했다. 최초 계획의 제안값 중 실제 API·화면으로 확정한 내용이다.

## 1. 전체 필터 update와 구독 한 개

0.10.2 서버의 [`session.ts`](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/session.ts)에서 구독은 filter만 받아 시작하고, sort/page는 초기 목록 조회에만 적용한다.
[`agent-updates-service.ts`](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/session/agent-updates/agent-updates-service.ts)의 발행은 초기 페이지 밖에서도 filter를 적용한다.
따라서 directory에 owned subscription 하나를 두고 이후 페이지는 구독 없이 읽는다. 실제 로컬 목록 296개를 2페이지로 읽었고 구독은 한 개였다.
200개 밖의 update·삭제는 자동 테스트로 검증했다. 각 pill에서 조회하거나 이벤트마다 전체 목록을 다시 받지 않는다.

초기·복구 페이지 조회 중의 update는 journal에 보관하고 마지막에 병합한다. 삭제는 tombstone으로 처리하며 오래된 응답으로 되살리지 않는다.
최대 2,000개 모델·10페이지·4,000개 journal을 넘기면 부분 결과로 표시한다. 수동 재시도 역시 single-flight다.

원시 데이터의 key는 호스트별 플러그인 인스턴스의 namespace와 ID를 조합한다. 뷰 상태·대화 이동에는 실제 UI host ID를 사용한다.
다른 호스트 인스턴스의 자료를 모으거나 연결하지 않는다.

## 2. 연결과 정리

`client.paseo`는 borrowed `PaseoApi`이며 연결 상태 API를 별도로 제공하지 않는다. 구독의 공개 `subscriptionId`가 null인지 로컬에서 확인한다.
뷰가 보일 때만 1초 타이머를 유지하며 네트워크 호출은 없다. 재연결 snapshot이 오면 기존 캐시를 유지하면서 페이지를 채운다.
구독 오류·초기 조회 실패는 마지막 구조/확인 불가로 표시한다. 연결 단절을 에이전트 완료·정상·0개 실행으로 바꾸지 않는다.
dispose는 조회를 취소하고 observer·timer·owned lease를 정리한다. borrowed Paseo 연결은 닫지 않는다. 재시도 release 중 dispose도 기다린다.

## 3. 그래프 배치 상한과 시각 구성

제안한 176×64는 두 줄 기본 글자와 상태가 좁아 **176×80**으로 확정했다. 간격은 가로 16, 세대 32, 바깥 24다.
관계선은 React Native View의 `left/top`으로 배치한다. 같은 부모의 겹치는 연결선을 하나의 가로 연결선으로 합쳐 불필요한 뷰와 진한 중첩을 줄인다.

최초 제안의 ‘펼친 노드 200개 이후 목록 전환’은 실제 209개 구조를 열자마자 목록으로 바꾸어 사용자 목적에 맞지 않았다.
**배치 좌표는 모델 상한 2,000개까지, 실제 노드 뷰는 viewport 주변에서 최대 200개**로 바꿨다. 2,000개 전체 펼침의 순수 모델·배치 중앙값은 약 2.65ms였다.
200개 초과 구조도 기본 그래프를 유지한다. 너무 넓은 직계 자손은 가로 스크롤이나 접이식 목록을 사용한다. force layout·노드 드래그·미니맵은 추가하지 않았다.

상태·제목은 topology signature에서 제외하므로 좌표가 변하지 않는다. 배율·관계 변경은 선택 노드 위치를 보정한다.
모달과 패널은 상태를 공유하되 스크롤을 각각 저장한다. 처음 패널을 열 때 실제 viewport가 측정된 뒤 현재 선택 노드를 중심으로 표시한다.

mac-monitor를 참고해 기본 글자 크기, 테마 기반 상태 점, 배경 카드, 작은 버튼, 8/12의 여백을 사용한다.
상세와 범위 선택은 카드로 구분하고, 반복 설명이나 애니메이션을 추가하지 않았다.

## 4. 모달 높이와 클릭

0.10.2의 `Modal.Content scrollable={false}`는 내부적으로 데스크톱 높이를 85%로 고정한다. 실제 큰 화면에서 과한 빈 공간이 생겼다.
모달은 기본 scrollable 설정으로 자연스러운 높이를 사용하고, 그래프 영역만 360(compact 300)으로 확보한다. 상세는 184(compact 168) 높이의 내부 스크롤이다.
패널에서는 그래프가 남은 영역을 채운다. 모달 헤더·compact 시트·Escape는 호스트가 담당한다.

mac-monitor와 같은 바깥 Pressable guard로 React portal의 클릭이 pill action을 재실행하지 않게 한다.
실제 모달과 React DOM portal 재현에서 노드·확대·ID 복사·본문 클릭 뒤 열린 상태와 배율이 유지됐다.

## 5. ID 복사와 범위

공개 `copyText` API로 선택한 에이전트의 실제 ID만 복사한다. 상세 카드 상단의 **ID 복사**는 키보드로도 접근 가능한 명시적 버튼이다.
노드·목록 행의 `onLongPress`도 같은 복사 경로를 사용한다. 성공·실패는 호스트 toast로 표시한다.
0.10.2에는 공개 context menu API가 없어 우클릭 메뉴는 넣지 않았다. DOM 이벤트나 클립보드 전역 접근으로 우회하지 않는다.

작업 제어·provider 내부 수집·타임라인 읽기·다른 호스트 설치는 추가하지 않았다. 로컬 설치와 검증만 수행하고 GitHub push는 하지 않는다.

## 6. 많은 subagent 탐색과 정적 D3 전환 — 0.1.1

사용자가 많은 subagent에서 이동이 불편하다고 보고하고 D3 force graph 전환과 비용 검토를 요청했다.
최초의 가로 계층 배치는 208개의 직계 자손을 한 줄에 펼쳐 수만 픽셀을 이동해야 했고, 기존에는 마우스 드래그 이동도 없었다.
단순히 세로로 바꾸어도 목록이 길어지는 문제는 남아 **정적 force 배치 + 전체 점 보기 + 검색 + 드래그**로 바꿨다.

- `d3-force@3.0.0`을 npm 의존성으로 사용한다. D3에는 복사한 노드·링크만 전달해 원본 에이전트 모델을 바꾸지 않는다.
- `forceSimulation(...).stop()` 후 수동 120 tick만 실행한다. 자동 타이머로 계속 움직이는 애니메이션은 사용하지 않는다.
- UI에서 약 6ms의 계산 뒤 다음 타이머로 넘긴다. 한 tick이 예산을 넘을 수 있으며 2,000개 fixture의 최대 tick은 약 18ms였다. worker를 제공하지 않는 0.10.2 RN 환경에서의 절충이다.
- 구조·접힌 가지가 같으면 플러그인 인스턴스의 최근 4개 좌표를 다른 에이전트의 뷰에서도 재사용한다. 캐시가 에이전트별로 계속 쌓이지 않게 했다. 상태·이름·선택·배율만 바뀔 때 새 시뮬레이션을 만들지 않는다. 닫기·모드 전환은 진행 중 작업을 중단한다. 자료 상한으로 목록에 폴백한 경우 tick은 실행하지 않는다.
- 최초 전체 맞춤은 3~100%, 확대 범위는 3~150%다. 60% 미만은 점, 그 이상은 카드다. 화면 주변에 카드가 200개 넘으면 점으로 그려 잘린 노드를 만들지 않는다.
- 점은 상태 색을 쓰며 현재 대화·선택을 테두리로 구분한다. hover/선택 이름과 상세는 기본 글자 크기로 읽는다. 선택한 노드의 조상 경로만 강조한다.
- 공개 RN `PanResponder`로 양방향 화면 이동을 구현했다. 드래그 뒤 발생하는 클릭·길게 누르기를 잠시 억제하고, 그래프 이름·상태의 텍스트 선택을 막는다. 상세 카드와 ID 복사는 유지한다.
- 이름·ID 검색은 자료를 필터링해 관계를 숨기지 않는다. 결과의 조상을 펼치고 선택한 위치를 최소 75%로 확대한다. 부모 선택 시 상단에서도 접기·펼치기를 제공한다.
- compact는 기존 가상화 목록을 유지한다. DOM·Canvas·SVG·새 소켓·서버 수집은 추가하지 않는다. 기존 계층 배치 함수는 비교용 benchmark에 남긴다.

초기 배치 비용과 2,000개 화면 렌더링 비용을 혼동하지 않는다. 209개 실제 화면은 검증했으며 전체 CPU·RSS·FPS와 실제 모바일·2,000개 화면은 미계측이다.
측정과 실행 결과는 VALIDATION에 기록한다. 이 변경도 로컬 설치만 반영하며 GitHub에는 push하지 않는다.

참고: [D3 simulation의 stop/tick](https://d3js.org/d3-force/simulation), [충돌 force](https://d3js.org/d3-force/collide), [RN PanResponder](https://reactnative.dev/docs/panresponder).

## 7. iOS의 pill 누락과 번들 문법 호환 — 0.1.2

사용자는 같은 iOS 앱에서 mac-monitor는 보이지만 agent-graph pill은 보이지 않는다고 보고했다. 플랫폼을 숨기는 조건은 없었다.
실제 로컬 데몬의 client catalog에서 0.1.1 번들을 받아 RN 0.81.5에 포함된 Hermes 컴파일러에 전달하자 `AgentDirectory`, `GraphViewState`, `GraphViews`의 클래스 표현식에서 `Invalid expression encountered`가 발생했다.

Paseo 0.10.2의 [`compiler.ts`](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/server/src/server/plugins/compiler.ts)는 client를 es2020으로 묶고 async 문법과 CommonJS interop을 보정하지만 클래스 문법은 변환하지 않는다.
이 번들은 앱의 [`evaluate.ts`](https://github.com/getpaseo/paseo/blob/v0.10.2/packages/app/src/plugins/evaluate.ts)에서 문자열로 평가된다. 따라서 iOS는 pill 등록 전에 구문 분석에서 멈출 수 있고, 데몬의 `running`·`Plugin ready`만으로 client 로드 성공을 확인할 수 없다.
mac-monitor의 client 진입 경로에는 해당 클래스 문법이 없다. D3 계산이나 모바일 표시 조건이 이번 재현의 원인은 아니다.

- 세 클래스를 함수와 closure로 생성하는 방식으로 바꿨다. 구독·캐시·세대 검사·정리와 뷰 상태의 공개 동작은 유지한다.
- `esbuild@0.28.1`을 검증용 개발 의존성으로 추가해 0.10.2 client compiler와 같은 주요 설정으로 제품 entry를 묶는다. 새 제품 런타임 의존성은 추가하지 않는다.
- 이전 문법이 Hermes에서 실패하는 재현, 새 전체 번들의 Hermes 컴파일, iOS 형태의 pill 등록·탭·compact 목록을 자동 검증한다.
- 로컬 reload 후 실제 데몬이 배포하는 수정 번들도 Hermes 컴파일을 통과했다. 0.11 미검증 호환 범위는 확대하지 않는다.

실제 iPhone 화면을 직접 제어하지 못했으므로 표시·터치 확인까지 완료했다고 기록하지 않는다. 데몬 재시작·mac-monitor 변경·GitHub push는 수행하지 않는다.

## 8. 모바일 그래프와 작은 화면 탐색 — 0.1.3

사용자가 모바일의 그래프 지원 여부를 물은 뒤 UI/UX를 개선하며 진행하도록 요청했다. 목록 강제는 D3의 플랫폼 제한이 아니라 초기 설계의 선택이었다. compact도 그래프를 기본으로 제공하고 `그래프 / 목록`으로 직접 전환하게 했다. SDK·지원 버전·기존 구독 방식은 유지한다.

- 모바일에서는 중첩 ScrollView 대신 고정된 영역 안에서 RN View 좌표를 이동한다. 한 손가락 드래그와 두 손가락 핀치를 PanResponder로 처리하며, 두 손가락의 중심 아래 좌표를 유지한다. 손가락 수가 바뀌면 시작점을 다시 잡는다. 이동 직후 탭·길게 누르기는 잠시 억제한다.
- 터치 중 위치 갱신은 약 16ms로 합치고 핀치 배율은 종료할 때 공유 상태에 한 번 저장한다. 상태 이벤트로 force 배치를 다시 만들지 않는다. 목록 모드는 D3 작업의 생성도 건너뛴다. 상시 물리 애니메이션·추가 조회·런타임 라이브러리는 추가하지 않는다.
- 축소된 점은 화면 기준 44의 터치 영역을 사용한다. 영역이 겹치면 실제 터치 지점에 가장 가까운 점을 선택한다. 빈 공간에서 먼 에이전트를 임의로 선택하지 않는다.
- 선택 정보는 이름·상태·ID 복사와 `상세`만 남긴 76 높이 요약으로 줄였다. 상세는 위로 펼쳐 그래프를 덮으며 요약 버튼과 그래프의 크기·위치를 바꾸지 않는다. 이름의 `↗`와 `현재 위치`는 해당 노드를 최소 75%로 확대한다.
- 검색은 `찾기`를 누를 때만 펼친다. 그래프 높이가 160 미만이면 배율 버튼으로 확대 도구를 열고, 64 미만이면 가려질 도구를 숨긴다. 검색 때문에 공간이 줄어도 하단 버튼은 유지한다. 기본 글자 크기·테마 색을 사용한다.
- 브라우저 미리보기에서 확대 직후의 scrollTo가 이전 콘텐츠 크기로 잘리는 문제를 찾았다. 새 배율의 화면 크기를 렌더링한 다음 이동해 선택 카드가 중앙에 표시되게 했다. 초기 배치 완료가 사용자의 확대율을 덮어쓰지 않게 수동 조작을 기록한다. 핀치 도중 배치·viewport가 바뀌면 현재 배율과 마지막 손가락 위치에서 조작을 이어 간다.
- compact 모달은 `scrollable={false}`로 호스트 시트 안의 남은 높이를 쓴다. 데스크톱의 자연스러운 모달 높이와 스크롤은 유지한다. 기존 4절의 compact 고정 그래프·상세 높이와 6절의 모바일 목록 강제는 이 규칙으로 대체한다.

RN Web 미리보기는 실제 제품 컴포넌트와 합성 데이터를 사용한 레이아웃·마우스 확인이다. iOS 이벤트 모양의 자동 테스트와 Hermes 문법 검사를 함께 수행하지만 실제 iPhone의 시트 제스처 경합·키보드·VoiceOver·FPS를 검증한 것으로 기록하지 않는다. 로컬 agent-graph만 반영하며 GitHub push는 하지 않는다.

## 9. 현재 워크스페이스 탐색과 대화 이동 — 0.1.4

사용자는 그래프 외에도 현재 워크스페이스의 에이전트를 최신순으로 보고 클릭해 대화에 focus하는 탐색 기능을 요청했다. 첫 pill 화면을 `탐색`으로 바꾸고 기존 그래프·트리 목록을 `구조` 탭에 유지한다. 탭·정렬·검색·스크롤은 호스트/workspace/원래 대화별 메모리 상태로 보존한다.

- 탐색 목록은 정확한 `workspaceId` 일치와 미보관 조건으로 필터링한다. 그래프의 workspace 범위와 달리 다른 workspace의 조상·자손을 포함하지 않는다. pill 수치도 이 목록의 총수·실행 수와 일치한다. 기존 그래프 범위와 형제 생성순은 유지한다.
- 기본 최근 활동순은 유효한 `updatedAt`/`createdAt` 중 최신 시각이다. API의 updatedAt은 이름·상태·설정 갱신도 포함하며 타임라인의 마지막 메시지 시각으로 주장하지 않는다. 정렬 버튼으로 최신 생성순을 선택할 수 있다. 동률은 생성시각·ID로 안정적으로 정렬하며 잘못된 시각은 정상 현재 시각으로 만들지 않는다.
- 기존 `sameAgent`는 updatedAt만 바뀐 이벤트를 알리지 않아 탐색 정렬이 오래된 상태로 남을 수 있었다. 시각을 표시값에 포함하되 알림은 기존 250ms 배치를 사용한다. 관계 signature는 시각을 포함하지 않으므로 D3 배치를 다시 계산하지 않는다.
- [0.10.2 공개 navigation 계약](https://github.com/getpaseo/paseo/blob/v0.10.2/public-docs/plugins/reference.md#surfaces-and-sidebar-items)과 설치된 타입에서 `PluginSurfaceProps`/패널만 `navigation.openAgent`를 제공한다. pill/icon props에는 없다. pill의 클릭은 인스턴스 내부 closure에 host/workspace/origin/target을 저장하고 등록한 `agent-browser` surface를 공개 `openSurface`로 연다. surface는 이동 의도를 한 번 소비해 `openAgent({agentId, serverId})`를 호출한다. 재렌더링·다시 방문해도 과거 요청을 반복하지 않는다. private router·전역·DOM·새 RPC로 우회하지 않는다.
- 클릭 시점과 전달 시점에 대상이 제거·보관되거나 원래 workspace에서 이동했는지 확인한다. 탐색은 현재 workspace만 허용한다. 구조에서 선택한 다른 workspace의 실제 자손은 대상 workspace도 전달해 기존 관계 탐색·대화 이동을 유지한다. 다른 host context·이동 실패·navigation 부재는 안내하며 임의의 대화를 열지 않는다. 이동 API가 없으면 행 이동을 비활성화하고 ID 복사는 유지한다. surface 열기 실패는 pill을 닫지 않고 이전 context로 복구한다.
- `크게 보기`는 탐색과 compact 구조에서 같은 context의 공개 전체 화면을 연다. 데스크톱 구조는 기존 작업 패널을 유지한다. 일상 탐색은 별도 sidebar 등록 없이 pill에서 접근한다. 실제 대화의 기존 탭 선택·focus·경로 처리는 Paseo에 맡긴다.
- 목록은 FlatList로 가상화하고 스크롤 오프셋을 유지한다. 시각 문자열은 정렬 때 항목당 계산해 비교마다 파싱하지 않는다. pill의 workspace별 집계는 snapshot당 한 번 만든다. 탐색에서는 D3 작업이 없으며 구독·조회 상한·연결 감시 방식·SDK·런타임 의존성은 그대로다.

행 이동·ID 복사·portal 클릭 경계·정렬·시각 이벤트·host/제거/navigation 실패·요청 중복 실행을 자동 검증한다. RN Web의 실제 컴포넌트 미리보기와 Hermes 검사는 실제 Paseo/iPhone 화면 전환·기존 탭 focus 검증과 구분해 기록한다. 원격 push는 수행하지 않는다.

## 10. 탐색 UI와 작은 화면의 도구 배치 — 0.1.5

사용자는 현재 UI를 개선해 달라고 요청했다. 실제 Paseo에서 중첩된 카드 테두리·반복 ID 버튼·항목이 적을 때의 빈 공간을 확인하고, 탐색 목적에 맞춰 목록을 간소화한다. 기본 글자 크기와 테마 색, 기존 데이터 수집과 이동 API는 유지한다.

- 탐색 행은 구분선 중심의 80 높이로 통일한다. 현재 대화에는 왼쪽 표시선과 옅은 배경을 사용하고, 상태·현재 표시·시각을 같은 행에 둔다. 이름은 최대 두 줄로 표시한다. 복사 아이콘과 검색 지우기·큰 보기 아이콘은 최소 44의 누름 영역과 접근성 이름을 유지한다. 복사 영역은 대화 이동 영역과 분리한다.
- 활동순/생성순은 두 탭에서 직접 선택한다. 이미 선택된 탭을 다시 눌러도 다른 정렬로 바뀌지 않는다. 검색 결과가 하나일 때만 Enter로 대화를 연다. 결과가 없거나 여러 개면 임의의 항목으로 이동하지 않는다. 최초 조회 실패는 `불러오는 중`으로 남기지 않고 실패 표시와 다시 읽기를 제공한다.
- 데스크톱 탐색은 최대 폭 760으로 읽는 폭을 제한한다. 모달 목록 높이는 검색 전 워크스페이스 항목 수를 기준으로 160~400 사이에서 정한다. 검색 결과 수가 줄어도 창 높이가 변하지 않는다. 패널과 compact 목록은 남은 높이를 사용한다. 기존 가상화·스크롤 저장을 유지한다.
- compact 구조에서는 범위 선택과 그래프/목록 아이콘을 같은 도구 행에 두고, 개수·현재 위치·찾기를 한 행에 묶는다. 320×520 미리보기에서 기존보다 그래프 영역 약 32를 확보했다. 확대·검색·선택 상세는 기존 접이식 동작을 유지한다.
- 구조 목록의 첫 위치 맞춤은 실제 FlatList layout 높이를 확인한 뒤 수행한다. 이전에는 높이 0인 상태의 viewPosition 계산으로 맨 위 항목이 잘렸다. RN Web에서 최초 scrollTop 32를 재현했고 수정 후 0을 확인했다. 상태 갱신마다 위치를 다시 맞추지는 않는다.
- 데스크톱의 큰 보기는 탐색·구조 모두 공개 workspace 작업 패널로 연다. 앞 절의 탐색 전체 화면 방식은 이 변경으로 대체한다. 실제 전체 화면의 내부 이름 `agent-browser` 대신 한국어 작업 탭 `에이전트`를 보여 주고 기존 대화 탭과 워크스페이스 문맥을 유지한다. compact는 기존 공개 전체 화면을 사용한다. 0.10.2의 sidebar 없는 surface는 호스트 헤더 제목을 따로 지정할 수 없어 내부 이름이 표시될 수 있다. 이를 위해 불필요한 sidebar 항목을 추가하지 않는다.

실제 Paseo 데스크톱 다크 화면에서 행 클릭이 이미 열려 있는 대화를 선택하고 중복 탭을 만들지 않는 것을 확인했다. 새 큰 보기 작업 탭과 구조 목록의 첫 행도 직접 확인했다. 합성 데이터의 라이트·다크·좁은 화면 검토와 실제 iPhone 검증은 구분한다. 구독·목록 조회·정적 D3 계산·런타임 의존성은 추가하지 않았고 GitHub push는 수행하지 않는다.


## 11. 최근순 탐색만 유지 — 0.1.6

사용자는 Paseo 기본 subagent 보기가 있어 별도 그래프의 필요성이 낮다고 판단했고, 제시한 선택지 중 **최근순 목록·검색·대화 이동·ID 복사만 남기기**를 선택했다. 자주 대화를 찾는 용도에 맞춰 그래프·구조 탭·관계 상세·접기·배율·드래그·핀치와 D3 의존성을 제거한다. 3~6절과 8~10절의 그래프 관련 규칙을 이 결정으로 대체한다. 기존 계획은 최근순 탐색 중심으로 다시 작성하고 이전 설계는 이 문서와 Git 이력에 남긴다.

- 첫 화면에서 목록과 검색이 바로 보인다. 검색 옆에 큰 보기 아이콘을 두어 별도 도구 행을 없앤다. 활동순/생성순 선택, 상태·현재 대화 표시, ID 복사와 길게 누르기는 유지한다. pill은 데스크톱·compact 모두 `에이전트 N`으로 줄인다.
- 검색·개수·행 제목의 좌측 여백을 12로 맞춘다. 표시선은 absolute 위치여서 이름을 밀지 않는다. 구역 간격 12, 가까운 요소 4/8을 사용하며 데스크톱 버튼 32, compact 버튼 44의 누름 영역을 확보한다. 목록 가상화·고정 행 높이·검색 전 개수 기준 모달 높이·화면별 스크롤 저장을 유지한다.
- 공개 대화 이동·구독 수명·페이지 경합·단절/오류 처리·iOS Hermes 호환 경로를 유지한다. 다른 workspace 대상은 목록·pill 전달·공개 surface에서 모두 차단한다. 이전 구조 보기의 외부 workspace 자손 이동 허용은 제거한다.
- 그래프 전용 소스·좌표 캐시·배치 타이머·관계 모델·관련 테스트/benchmark를 제거한다. 상태 정규화 검증은 별도 파일로 유지하고 benchmark는 최근 목록의 필터·정렬·검색으로 바꾼다. 새 런타임 의존성은 추가하지 않는다.
- 기존 설치 호환을 위해 plugin ID `agent-graph`, panel/pill ID `graph`와 Command Center ID는 유지한다. 화면은 한국어 `에이전트`이며 아이콘은 목록으로 바꾼다. 검색·정렬·스크롤 상태는 기존과 같은 host/workspace/origin 단위 메모리 상태다.

실제 Paseo와 RN Web 미리보기의 확인 범위, 설치 번들 축소와 비용은 VALIDATION에 기록한다. 실제 iPhone 검증은 완료로 쓰지 않으며 이번에도 로컬 반영과 로컬 커밋만 진행한다.

## 12. 목록에서 대화 닫기와 표시 간소화 — 0.1.7

사용자는 ‘바로 닫기’를 탐색 창이 아닌 목록의 각 에이전트 대화를 닫는 기능으로 명확히 했다. 복사 아이콘 옆의 작은 ×와 짧은 확인 창을 추가한다. 일반 목록에는 종료 경고나 설명을 반복하지 않는다.

- Paseo 0.10.2의 공개 plugin navigation에는 탭만 닫는 API가 없다. 기본 대화 목록의 닫기와 같은 공개 `agents.ref(id).archive()`를 사용한다. 보관함으로 이동하며 실행 중인 세션과 연결된 하위 에이전트도 닫힐 수 있으므로 확인 창에서 범위를 설명한다. 임의의 private router·브라우저 탭 조작이나 별도 중단 API를 사용하지 않는다.
- 캐시의 원래 workspace를 확인하고, 실행 직전 `refresh()`에서 정확한 ID·workspace·미보관 조건을 다시 확인한다. 단절·대상 이동·삭제·보관·dispose 중에는 새 닫기 요청을 보내지 않는다. 같은 대상의 연속 요청은 한 번으로 합친다.
- 성공 응답 뒤에만 행을 제거한다. 실패는 목록과 확인 창을 유지하고 재시도할 수 있다. 확인·취소·복사와 행 이동은 독립적이며 portal 클릭이 원래 pill을 재실행하지 않는다. 하위 에이전트 보관은 Paseo 이벤트로 반영한다.
- 검색의 채움 배경과 정렬 그룹의 바탕을 줄이고 개수 표시는 숫자만 남긴다. compact에서는 오늘 항목의 시간 또는 이전 항목의 날짜만 표시해 두 개의 44 누름 영역을 확보한다. 전체 시각은 접근성 이름에 유지한다. 기본 글자 크기·80 행 높이·목록 가상화·공유 구독은 유지한다.
- 닫기를 확인한 경우에만 대상 조회 한 번과 보관 요청 한 번이 추가된다. 유휴 목록 조회, 런타임 의존성, 서버·소켓·헬퍼는 추가하지 않는다.

사용 중인 대화의 실제 보관은 검증 과정에서 수행하지 않는다. 대상·응답·실패·중복·페이지 경합은 대역으로, 실제 Paseo에서는 확인·취소와 표시를 점검한다. 실제 iPhone 검증은 별도로 남긴다.

## 13. 아이콘 호버와 포커스 피드백 — 0.1.8

사용자는 아이콘 호버 등을 포함해 UI/UX를 개선해 달라고 요청했다. 최근 목록의 간결한 구성과 기본 폰트는 유지하고, 조작 가능한 영역과 위험 동작을 필요한 순간에만 구분한다.

- 아이콘·정렬 버튼·행 이동 영역에 RN Pressable의 호버·포커스 피드백을 추가한다. 기본 상태는 중립색, 호버·누름은 `surface2`, 포커스는 `accent` 테두리다. 닫기 아이콘과 확인 버튼의 포커스는 `statusDanger`를 사용한다. 확인 절차나 보관 대상 검증은 바꾸지 않는다.
- 항상 같은 1의 테두리 공간을 확보해 호버·포커스로 크기가 바뀌지 않게 한다. 복사와 닫기 사이에는 4의 간격을 두고, 데스크톱 32·compact 44·행 높이 80을 유지한다.
- 검색 포커스는 기존 외곽 테두리의 색으로 표시한다. 웹에서는 테마 포커스를 표시하는 동안만 기본 outline을 없애 중복 사각형을 제거한다. 호스트의 확인 창 취소 직후처럼 포커스 이벤트 없이 대상이 다시 선택되는 순간에는 기본 outline이 남아 표시가 완전히 사라지지 않는다. RN 타입이 지원하는 스타일만 쓰며 iOS의 네이티브 입력 동작은 유지한다.
- 닫기에는 확인 후 보관함으로 이동한다는 접근성 힌트를 둔다. 0.10.2에 공개 Tooltip 요소가 없고 반복 안내 문구에 대한 이전 피드백도 있어 자체 popup·portal·툴팁 타이머는 추가하지 않는다. 기능 이름은 기존 접근성 라벨로 유지한다.
- 호버·포커스는 각 컨트롤의 로컬 상태만 변경한다. 이동·복사·보관·목록 재조회를 실행하지 않는다. 비활성화 시 강조를 초기화하고, 새 런타임 의존성·구독·서버·폴링을 추가하지 않는다.

실제 Paseo의 포커스·확인/취소와 RN Web의 호버·키보드·좁은 화면 검증은 VALIDATION에 구분해서 기록한다. 실제 iPhone과 원격 CI는 확인한 것으로 쓰지 않는다.

## 14. 행 호버 배경의 여백 보완 — 0.1.9

사용자는 호버 영역의 패딩이 여전히 부자연스럽다고 지적했다. 0.1.8의 행 이동 영역은 왼쪽 패딩 0·오른쪽 8이었고, 높이 79의 배경이 구분선까지 붙었다. 오른쪽 아이콘 그룹과도 별도 간격이 없어 서로 다른 크기의 강조 영역이 이어져 보였다.

- 행 바깥 여백을 4로 두고 이동 영역의 좌우 패딩을 8, 상하 패딩을 4로 맞춘다. 글자 시작점은 기존 위치를 유지하며 행 강조 배경만 왼쪽으로 8 더 넓어진다.
- 행 이동 영역과 아이콘 그룹 사이에는 8을 둔다. 복사와 닫기 사이 간격 4, 데스크톱 32·compact 44의 버튼 크기, 행 높이 80과 가상화 계산은 유지한다.
- 행의 강조 영역은 높이 71이 된다. 위쪽 여백 4, 아래쪽 여백 4와 구분선 1로 배경과 구분선을 분리한다. 기본 글자 크기의 두 줄 제목·상태·시각이 영역 안에 들어가는지 320/390px 미리보기와 실제 데스크톱에서 확인한다.
- 색·기능·확인 흐름·구독·의존성은 바꾸지 않는다. 이 변경에는 구현을 반복하는 스타일 단위 테스트를 추가하지 않고, 기존 동작 회귀 검사와 실제 렌더링의 여백·크기·스크롤 유지로 검증한다.

## 15. mac-monitor와 비교해 강조 간소화 — 0.1.10

사용자는 호버 영역이 부자연스럽다는 피드백 뒤 mac-monitor와 비교해 달라고 요청했다. 실제 Paseo 화면과 두 플러그인의 코드를 비교했다. mac-monitor의 정렬 버튼은 라벨 주변 좌우 4·상하 6·모서리 4를 사용하고, 앱 행에는 자체 호버 배경이 없다. 선택·누름 상태를 작은 영역에 표시한다. agent-graph는 버튼 좌우 12·모서리 8과 큰 행 호버 배경을 함께 사용해 강조가 더 많았다.

- 정렬·텍스트 버튼은 좌우 4·상하 6·모서리 4로 맞춘다. 선택한 정렬은 강조색 대신 기본 글자색과 굵기 600으로 구분한다. 아이콘 모서리도 4로 맞추되 가운데 정렬과 고정 누름 영역은 유지한다.
- 행 이동 영역의 자체 호버 배경을 제거한다. 누름 배경과 키보드 포커스 테두리, 현재 대화의 표시선·배경은 유지한다. 아이콘과 정렬 버튼의 작은 호버 배경은 남겨 조작 위치를 구분한다.
- mac-monitor의 스타일을 모두 복제하지 않는다. 기존 compact 44·데스크톱 32의 누름 영역과 검색·위험 동작의 포커스 표시를 유지한다. 0.1.9의 좌우 균등 패딩·아이콘 간격·행 높이 80·가상화·스크롤 보존도 유지한다.
- 표시 방식만 바꾸며 조회·구독·닫기 확인·대상 검증·런타임 의존성은 바꾸지 않는다. 기존 상호작용 회귀 검사를 새 행 포커스 표현에 맞추고, 스타일 수치를 반복하는 단위 테스트는 추가하지 않는다.

mac-monitor는 읽기와 화면 비교에만 사용했다. 로컬 agent-graph만 반영하며 실제 iPhone 확인이나 GitHub push를 완료했다고 쓰지 않는다. 검증 결과는 VALIDATION에 기록한다.
