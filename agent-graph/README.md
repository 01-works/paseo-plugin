# agent-graph

현재 워크스페이스의 Paseo 에이전트를 pill에서 찾아 대화로 이동하는 플러그인입니다. 부모·자식 관계는 정적 D3 force 그래프와 접이식 목록으로 볼 수 있습니다. **Paseo 0.10.2**, 플러그인 0.1.4 기준입니다.

## 설치

현재 구현은 로컬 저장소에 있습니다. 이 구현의 GitHub push는 아직 진행하지 않았습니다.

```sh
cd agent-graph
npm ci
paseo plugin install "$PWD"
```

설치 후 에이전트 입력창의 `에이전트 N · 실행 R` pill을 누릅니다. 숫자는 현재 워크스페이스의 미보관 에이전트 수이며, 100개 이상이거나 compact 화면에서는 `에이전트 N`으로 줄여 표시합니다.
플러그인 사용은 Paseo 설정에서 활성화되어 있어야 합니다.

0.1.2에서 iOS pill의 번들 문법 문제를 수정했고, 0.1.3에서 모바일 그래프·터치를 추가했습니다. 0.1.4는 탐색 목록을 첫 화면으로 제공합니다. 이전 버전을 사용했다면 소스를 갱신하고 reload합니다.

수정 반영은 `paseo plugin reload agent-graph`, 비활성화·복귀는 `paseo plugin disable agent-graph`와 `paseo plugin enable agent-graph`입니다.
제거는 `paseo plugin remove agent-graph`입니다. 데몬을 재시작할 필요가 없습니다.

## 사용

- **탐색:** pill을 처음 열면 현재 워크스페이스의 미보관 에이전트만 최근 활동순으로 보여줍니다. 다른 워크스페이스의 조상·자손은 이 목록에 포함하지 않습니다. `현재`와 강조 테두리는 pill을 연 대화입니다.
- **최근순:** `최근 활동 ↓`를 누르면 최신 생성순으로, 다시 누르면 최근 활동순으로 바뀝니다. 활동순은 API의 `updatedAt`과 `createdAt` 중 최신 유효 시각을 사용하며 이름·설정·상태 변경도 포함합니다. 생성순은 `createdAt` 기준입니다. 표시 시각은 기기의 현지 시각입니다.
- **대화 이동:** 탐색 행을 누르면 해당 에이전트 대화를 엽니다. 이미 열린 대화의 선택·포커스 처리는 Paseo의 공개 `navigation.openAgent`에 맡깁니다. pill에는 이 API가 없어 등록한 공개 화면을 잠시 거쳐 이동합니다. 공개 화면과 작업 패널에서는 직접 호출합니다. 이동 API가 없는 앱에서는 안내와 ID 복사를 제공하고 이동 버튼을 비활성화합니다.
- **빠른 검색·복사:** 탐색 입력창에서 이름·ID로 목록을 좁힙니다. 각 행의 `ID` 버튼과 길게 누르기는 이동 없이 ID만 복사합니다. 검색·정렬·스크롤은 보기 전환 뒤에도 유지합니다.
- **구조:** 상단 탭으로 관계 그래프·접이식 트리 목록에 전환합니다. 탐색의 최신순 정렬은 그래프의 형제 순서와 좌표에 영향을 주지 않습니다.
- **현재 구조:** 현재 에이전트의 루트와 그 아래 자손을 봅니다. 같은 호스트의 다른 workspace에 있는 자손도 포함합니다.
- **워크스페이스:** 해당 workspace의 에이전트와 자손, 관계를 이해하는 데 필요한 조상을 봅니다.
- **노드 선택:** 아래 카드에 이름·상태를 표시합니다. 모바일에서는 `상세`를 눌러 provider/model·workspace·부모·ID를 펼칩니다. 선택한 이름의 `↗`를 누르면 그 위치를 확대합니다.
- **ID 복사:** 상세 카드의 버튼을 누릅니다. 노드를 길게 눌러도 ID를 복사합니다. 실패하면 오류를 표시합니다.
- **접기·펼치기:** 노드 옆 버튼이나 선택한 부모의 상단 버튼으로 가지를 접습니다. `+N`은 숨겨진 자손 수입니다.
- **전체 보기:** 처음에는 전체 구조를 화면에 맞춥니다. 축소 상태에서는 점과 연결선으로 표시하며 선택한 이름·상태는 아래 카드에 표시합니다. 데스크톱에서는 점 위에 마우스를 올려 이름을 볼 수도 있습니다. 선택한 에이전트에서 부모로 이어지는 경로를 강조합니다.
- **확대·이동:** 3~150% 범위에서 확대합니다. 60% 이상에서는 이름·상태 카드로 전환합니다. 화면 주변에 200개 넘는 카드가 몰리면 점 보기를 유지합니다. 데스크톱은 마우스 드래그·양방향 스크롤, 모바일은 한 손가락 이동·두 손가락 핀치를 사용합니다. `맞춤`으로 전체 구조에 복귀합니다. 낮은 화면에서는 배율 표시를 눌러 확대 도구를 펼칩니다.
- **검색:** 모바일은 `찾기`로 입력창을 엽니다. 이름 또는 ID로 검색하고 Enter·이전/다음 버튼으로 결과를 선택합니다. 접힌 조상을 펼치고 해당 위치를 최소 75%로 확대해 보여줍니다.
- **현재 위치:** 현재 대화의 노드를 선택하고 화면 안으로 이동합니다.
- **크게 보기:** 탐색은 공개 전체 화면에서 이어 봅니다. compact의 구조도 전체 화면으로 열며, 데스크톱의 구조는 workspace 작업 패널로 엽니다. 같은 선택·접기·범위를 유지하고, 구조 상세의 `대화 열기`도 사용할 수 있습니다.
- **목록:** 구조 탭에서는 데스크톱·모바일 모두 그래프가 기본입니다. `목록`으로 전환하면 이름·상태를 접이식 목록에서 읽습니다. 이는 현재 워크스페이스를 최신순으로 보여주는 탐색 목록과 별도 보기입니다.

우클릭 메뉴는 Paseo 0.10.2의 공개 플러그인 API에서 제공하지 않아 추가하지 않았습니다.
탐색/구조 선택·정렬·검색·접기·배율은 플러그인이 켜진 동안 메모리에 유지됩니다. reload·disable·앱 재시작 뒤에는 초기화됩니다.
모달과 패널의 스크롤 위치는 각각 유지합니다. 에이전트를 생성·중단·수정하는 기능은 없습니다.

## 표시 기준

0.10.2의 원시 목록에서 `labels["paseo.parent-agent-id"]`를 읽어 관계를 구성합니다.
부모 필드가 별도로 존재하는 DTO에서는 그 값을 우선하며, 명시적 `null`은 부모 없음입니다.
관계가 없는 에이전트는 독립 루트로 표시합니다. 이름·workspace·프로세스 관계로 부모를 추측하지 않습니다.
Codex·Claude 안에서만 생성되고 Paseo에 등록되지 않은 하위 에이전트는 표시되지 않습니다.

상태는 색과 글자로 함께 표시합니다. 실행 중·시작 중·입력 필요·결과 확인·대기·오류·제공자 사용 불가·닫힘·확인 불가를 구분합니다.
`결과 확인`은 성공이나 전체 작업 완료를 뜻하지 않습니다. pill의 실행 수는 `running`만 포함합니다.
부모가 조회되지 않으면 `부모 정보 없음`, 순환은 문제 연결을 끊고 상세에 표시합니다. 조상 문맥은 실제 에이전트 수에서 제외합니다.

## 갱신과 한계

호스트의 기존 Paseo 연결을 사용하는 client 전용 플러그인입니다. 추가 서버·소켓·헬퍼·CLI 수집을 실행하지 않습니다.
호스트별 인스턴스의 여러 pill·모달·패널·탐색 화면이 directory 하나와 owned subscription 하나를 공유합니다.
처음에 200개씩 최대 10페이지를 읽고, 이후에는 이벤트를 약 250ms 단위로 묶어 반영합니다. 정상 연결에서 목록을 주기적으로 재조회하지 않습니다.
보이는 뷰가 있을 때만 구독의 로컬 연결 상태를 1초마다 확인합니다. 이 확인은 네트워크 요청을 보내지 않습니다.

모델은 최대 2,000개입니다. 상한·페이지 실패는 `일부만 표시`로 알리며, 단절 때는 마지막 구조와 `연결 끊김`을 유지합니다.
복구 snapshot을 받으면 페이지를 다시 채웁니다. 오류·부분 결과에서만 `다시 읽기`가 나타납니다.
페이지 조회 도중 도착하는 변경·삭제가 오래된 응답으로 되돌아가지 않도록 처리합니다.

D3는 최대 2,000개 좌표를 정하는 데만 사용합니다. 자동 시뮬레이션을 즉시 멈추고 120회의 계산을 약 6ms 단위로 나누어 실행합니다.
한 tick이 6ms를 넘을 수 있으므로 프레임 시간의 상한을 보장하는 방식은 아닙니다. 정리 중에는 초기 배치를 보여줍니다.
완료된 배치는 플러그인 인스턴스의 최근 4개를 캐시합니다. 같은 구조는 다른 에이전트의 pill에서도 재사용하며, 상태·제목 갱신이나 캐시에 있는 구조의 재열기는 물리 계산을 반복하지 않습니다.
화면 주변 노드만 그리며, 전체 보기는 최대 2,000개의 점, 카드 보기는 최대 200개를 표시합니다. 모바일도 같은 정적 배치 캐시를 사용합니다. 탐색과 트리 목록에서는 D3 작업을 만들지 않으며 가상화한 행만 표시합니다.
터치 이동 중에는 화면 위치를 최대 약 16ms 간격으로 갱신하고, 핀치 배율은 손을 뗄 때 공유 상태에 저장합니다. 실제 iPhone의 FPS·배터리·메모리 부하는 아직 측정하지 않았습니다.
노드 자체를 옮기거나 움직이는 애니메이션을 넣지 않습니다. 드래그는 화면 이동입니다.

현재는 **선택한 호스트의 Paseo 에이전트**만 표시합니다. 다른 Mac을 합친 fleet 그래프는 제공하지 않습니다.
0.11 이상의 API 호환성, 실제 iPhone의 pill·시트·터치와 테마 표시는 추가 검증이 필요합니다. RN Web 미리보기와 Hermes 문법 검사는 실기기 검증을 대신하지 않습니다.

## 검증·개발

```sh
npm run typecheck
npm test
npm run audit
npm run bench
npm run bench:force
# 실행 중인 로컬 데몬의 목록·구독을 읽기 전용으로 확인
node --import tsx test/manual/live.mjs
```

실제 로컬 목록 296개를 두 번의 페이지 조회와 구독 한 개로 읽고, 이후 5초 동안 반복 조회 0회를 확인했습니다.
0.1.1의 정적 force 배치 120 tick 중앙값은 209개 **127ms**, 500개 **367ms**, 2,000개 **1,815ms**였습니다.
이는 Node의 순수 배치 비용이며 실제 Paseo 렌더링 시간·전체 CPU·추가 메모리를 측정한 값은 아닙니다. 기존 `bench`는 초기 계층 배치의 비교용입니다.
실제 데스크톱 다크 화면의 209개 구조에서 전체 보기·카드 확대·드래그·이름 검색·접기/복원·ID 복사를 확인했습니다.
타입 검사·73개 테스트·DOM/기본 폰트 audit가 통과했습니다. 제품 entry와 실제 설치 번들을 React Native에 포함된 Hermes 컴파일러로 검증했습니다.
iOS 형태의 pill·그래프·한 손가락 이동·핀치·목록 전환은 호스트 mock 테스트로 확인했습니다. RN Web의 실제 컴포넌트 미리보기에서 320px 라이트·390px 다크와 데스크톱 배치, 검색·선택·복사·드래그를 확인했습니다. 실제 iPhone 터치·표시는 별도 확인이 필요합니다.
최초 설치의 disable/enable도 검증했습니다. GitHub workflow는 추가했으며 원격 실행은 아직 하지 않았습니다.

상세 결과는 [VALIDATION](docs/VALIDATION.md), 구현 중 판단은 [DECISIONS](docs/DECISIONS.md)에 기록합니다.
설계와 출처는 [PLAN](docs/PLAN.md), [REFERENCES](docs/REFERENCES.md)에서 볼 수 있습니다.
