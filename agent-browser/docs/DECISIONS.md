# agent-browser 설계 결정

현재 기준: **0.3.0 · 2026-10-11**. 구현 구조는 [PLAN](PLAN.md), 검증 범위는 [VALIDATION](VALIDATION.md)을 따릅니다.

## 초기 구독 실패 복구와 설치 준비

첫 목록 요청이 실패하면 에이전트별 pill도 등록되지 않아 안쪽의 수동 재시도에 접근할 수 없습니다.
구독 수립 실패에만 최대 30초의 지수 재시도를 적용하고, 수립 성공·수동 재시도·dispose와 예약 수명을 함께 관리합니다.
정상 구독 뒤의 갱신은 기존 owned subscription에 맡깁니다. 회귀 테스트는 entry부터 시작해 실패 뒤 pill이 생기는지 확인합니다.

제품은 호스트 제공 라이브러리와 로컬 코드만 사용하므로 manifest의 `npm ci` 준비 명령을 제거합니다.
개발·CI의 `npm ci`와 lockfile은 유지합니다. 기준은 [공식 Git 배포 안내](https://paseo.sh/docs/plugins/publishing#share-through-github-or-git)입니다.

## 0.3.0 · 오래된 대화 일괄 정리

기본 기간은 주말과 잠깐 멈춘 작업에 여유를 주는 7일이며 14일·30일을 선택할 수 있습니다.
생성일만으로 판단하지 않고 기존 활동순의 최근 변경 시각을 사용합니다. 이름·설정 변경도 포함하는 기준이며 마지막 메시지 시각과는 다릅니다.
버튼을 누르면 대상 목록을 먼저 보여주고 확인한 대화만 보관합니다. 열린 확인 창에 새 후보를 자동으로 추가하지 않습니다.
정리는 목록 전체를 관리하는 동작이므로 검색·정렬과 떨어진 목록 아래 오른쪽에 둡니다.
보관 아이콘·상시 테두리·배경으로 실행 버튼을 표시하고 접근성 선택 상태는 부여하지 않습니다. 확인 창의 기간 선택은 기존 선택형 표현을 유지합니다.

상위 보관이 하위 작업에 영향을 줄 수 있어 모든 미보관 하위가 정리 조건을 만족해야 상위를 후보에 넣습니다.
하위부터 순차 실행하며 매번 남은 하위를 조회하고 대상을 refresh합니다. 하위 실패·새 하위·진행 중인 턴·최근 활동은 상위 보관을 막습니다.
표시 상태에 오류나 닫힘이 우선하더라도 원래 실행·권한·activeTurn 플래그로 정리 가능 여부를 별도로 확인합니다.
일부 목록과 단절에서는 실행하지 않고 중단·화면 종료에서 후속 요청을 멈춥니다.

기존 client 연결·구독을 재사용합니다. 미리보기에는 새 요청이 없으며 실행 확인 때만 대상별 조회·보관 요청을 추가합니다.
기존 SDK 메서드만 사용하여 지원 범위는 `>=0.10.2 <0.12.0`을 유지합니다.

## 0.2.1 · Paseo 0.11.1 호환

SDK를 0.11.1로 올리고 지원 범위를 `>=0.10.2 <0.12.0`으로 확장했습니다.
새 `addScreen`·`openScreen`을 우선 사용하며, API가 없는 0.10.2 클라이언트에는 기존 화면 API를 사용합니다.
새 API의 실패를 구 API로 재시도하면 이동이 중복될 수 있으므로 메서드의 존재 여부로만 경로를 선택합니다.
구·신 API의 등록·이동·구독 해제는 자동 테스트로 확인하고 실제 앱 화면은 별도 검증으로 기록합니다.

## 0.2.0 · 이름과 설치

사용자의 독립 설치 요청에 따라 폴더·설치 ID는 `agent-browser`, 패키지는 `paseo-agent-browser`,
pill ID는 `browser`로 통일했습니다. 화면 이름은 `에이전트`를 유지하고 기존 설치 이름의 호환 경로는 제공하지 않습니다.
이름 변경으로 목록 처리·조회·런타임 의존성을 늘리지 않았습니다.

## 범위와 수집

Paseo의 기본 subagent 보기와 겹치는 구조 시각화를 줄이고 현재 워크스페이스의 탐색에 집중합니다.
최근 목록·검색·대화 이동·ID 복사·확인 후 닫기를 제공하며 원래 대화별 상태를 보존합니다.
기존 연결과 구독을 공유하여 여러 pill이 떠 있어도 정상 상태의 목록 조회를 반복하지 않습니다.

pill에는 navigation이 없으므로 공개 경유 화면을 이동에 사용합니다.
닫기는 영향 범위를 확인하고 공개 refresh·archive API로 처리하며, 성공 뒤에 목록을 갱신합니다.
