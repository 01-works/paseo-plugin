# 구현 결정 및 계획 보완

## 2026-10-06 · 서버의 설치 경로 탐색 (PLAN 5.2, 12절)

Paseo v0.10.2 `packages/server/src/server/plugins/compiler.ts`는 CommonJS 번들을 만들고,
`plugin-process.ts: evaluateBundle`은 `globalThis.eval`로 실행한다. 서버 컨텍스트에는
소스 경로나 데이터 디렉터리가 없으며 `import.meta.url`을 사용할 수 없다.

따라서 `PASEO_HOME`(없으면 `~/.paseo`)의 `config.json`에서 **mac-monitor 항목의 path만 읽어**
설치 디렉터리를 찾는다. 설정 파일을 직접 수정하지 않는다. `server-id`도 동일한 홈에서 읽는다.
설정 경로를 찾을 수 없으면 Node 모드로 폴백한다. `--id`로 다른 ID 설치는 지원하지 않는다.
테스트와 수동 대조 CLI는 root를 주입한다.

## 2026-10-06 · 오류 및 시계 처리 보완 (PLAN 5.2, 6절)

신선도는 서버 단조 시계 기준으로 판정하며 화면의 갱신 시각은 헬퍼의 절대 시각을 사용한다.
시계 조정으로 오래된 값이 정상 상태가 되는 것을 막는다. 메모리/CPU API 실패는 해당 값을
null로 표시하고 오류 상태를 반환한다. 압력만 실패하면 압력은 확인 불가이며 다른 수치는 유지한다.
프로세스 CPU는 PID/시작 시각이 같은 항목의 차이를 합산한다. 새 프로세스의 누적 CPU나 종료된
프로세스 때문에 그룹 CPU가 역행하는 것을 막기 위한 것으로 승인된 그룹별 Δ 공식의 구현 방식이다.

## 2026-10-06 · 부하 검증 방식 (PLAN 9.3절)

9.3절의 `ps` 관찰 예시 대신 사용자 제약(주기적 ps/top 금지)을 우선하여,
`test/manual/measure-load.c`로 libproc CPU 누적값을 관찰 시작·종료 두 번만 읽는다.
시간 변환에는 `mach_timebase_info`를 적용하며 RSS는 종료 시 `PROC_PIDTASKINFO`로 읽는다.
시스템 전용 / 앱 스캔 활성 모드를 각각 120초 관찰한다.

## 2026-10-06 · Node 폴백 실행 비용 (PLAN 5.2절)

2초마다 `vm_stat` 한 번과 여러 키를 함께 읽는 `sysctl` 한 번만 실행한다.
일부 sysctl 키 실패 시 성공한 stdout 키는 보존하며 누락된 필드만 null과 오류로 처리한다.
프로세스 상위 목록은 미지원이다. 리서치의 0.11%는 프로토타입 비용이며 이 구현의 보장 수치가 아니다.

## 2026-10-06 · pill 잘림 및 좁은 상세 창 수정 (PLAN 5.3절 변경)

사용자가 상세 창의 펼침 방향과 좁은 폭, RAM 잘림을 보고해 UI 개선을 요청했다.
v0.10.2 `packages/app/src/plugins/buttons/view.tsx`에서 pill은 `maxWidth: 160`,
라벨은 한 줄로 제한된다. 팝오버는 별도로 `minWidth=280`, `maxWidth=420`이며
composer 위쪽을 선호하지만 공간에 따라 위치가 달라질 수 있다. SDK에는 폭·방향 지정 옵션이 없다.

일반 화면에도 계획의 축약 라벨 `23% · 14.1G`를 적용하고 전체 용량은 상세에 유지한다.
`G`는 GiB이며 버튼 설명에도 단위를 명시한다. 요청에 따라 popover 대신 공식 0.10.2
`Modal`과 action 버튼을 사용한다. 데스크톱 기본 중앙 모달 폭은 최대 520px이고 compact는
호스트의 시트를 따른다. 고정 최소 폭을 제거하고 긴 CPU 설명을 두 행으로 나눠 좁은 화면의
넘침을 줄인다. 모달은 열린 동안만 내용을 mount하여 상세 폴링·앱 스캔 관심 규칙을 유지한다.
수집기·샘플 간격은 변경하지 않는다. 실제 테마·compact 화면 확인은 여전히 사용자 확인이 필요하다.
