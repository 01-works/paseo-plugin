# 구현 결정 및 계획 보완

## 2026-10-06 · 서버의 설치 경로 탐색 (PLAN 5.2, 12절)

Paseo v0.10.2 `packages/server/src/server/plugins/compiler.ts`는 CommonJS 번들을 만들고,
`plugin-process.ts: evaluateBundle`은 `globalThis.eval`로 실행한다. 서버 컨텍스트에는
소스 경로나 데이터 디렉터리가 없으며 `import.meta.url`을 사용할 수 없다.

따라서 `PASEO_HOME`(없으면 `~/.paseo`)의 `config.json`에서 **mac-monitor 항목의 path만 읽어**
설치 디렉터리를 찾는다. 설정 파일을 직접 수정하지 않는다. `server-id`도 동일한 홈에서 읽는다.
설정 경로를 찾을 수 없으면 Node 모드로 폴백한다. `--id`로 다른 ID 설치는 지원하지 않는다.
테스트와 수동 대조 CLI는 root를 주입한다.

## 2026-10-06 · 오류 및 시계 처리 보완 (PLAN 5.2, 6절)

신선도는 서버 단조 시계 기준으로 판정하며 화면의 갱신 시각은 헬퍼의 절대 시각을 사용한다.
시계 조정으로 오래된 값이 정상 상태가 되는 것을 막는다. 메모리/CPU API 실패는 해당 값을
null로 표시하고 오류 상태를 반환한다. 압력만 실패하면 압력은 확인 불가이며 다른 수치는 유지한다.
프로세스 CPU는 PID/시작 시각이 같은 항목의 차이를 합산한다. 새 프로세스의 누적 CPU나 종료된
프로세스 때문에 그룹 CPU가 역행하는 것을 막기 위한 것으로 승인된 그룹별 Δ 공식의 구현 방식이다.

## 2026-10-06 · 부하 검증 방식 (PLAN 9.3절)

9.3절의 `ps` 관찰 예시 대신 사용자 제약(주기적 ps/top 금지)을 우선하여,
`test/manual/measure-load.c`로 libproc CPU 누적값을 관찰 시작·종료 두 번만 읽는다.
시간 변환에는 `mach_timebase_info`를 적용하며 RSS는 종료 시 `PROC_PIDTASKINFO`로 읽는다.
시스템 전용 / 앱 스캔 활성 모드를 각각 120초 관찰한다.

## 2026-10-06 · Node 폴백 실행 비용 (PLAN 5.2절)

2초마다 `vm_stat` 한 번과 여러 키를 함께 읽는 `sysctl` 한 번만 실행한다.
일부 sysctl 키 실패 시 성공한 stdout 키는 보존하며 누락된 필드만 null과 오류로 처리한다.
프로세스 상위 목록은 미지원이다. 리서치의 0.11%는 프로토타입 비용이며 이 구현의 보장 수치가 아니다.

## 2026-10-06 · pill 잘림 및 좁은 상세 창 수정 (PLAN 5.3절 변경)

사용자가 상세 창의 펼침 방향과 좁은 폭, RAM 잘림을 보고해 UI 개선을 요청했다.
v0.10.2 `packages/app/src/plugins/buttons/view.tsx`에서 pill은 `maxWidth: 160`,
라벨은 한 줄로 제한된다. 팝오버는 별도로 `minWidth=280`, `maxWidth=420`이며
composer 위쪽을 선호하지만 공간에 따라 위치가 달라질 수 있다. SDK에는 폭·방향 지정 옵션이 없다.

일반 화면에도 계획의 축약 라벨 `23% · 14.1G`를 적용하고 전체 용량은 상세에 유지한다.
`G`는 GiB이며 버튼 설명에도 단위를 명시한다. 요청에 따라 popover 대신 공식 0.10.2
`Modal`과 action 버튼을 사용한다. 데스크톱 기본 중앙 모달 폭은 최대 520px이고 compact는
호스트의 시트를 따른다. 고정 최소 폭을 제거하고 긴 CPU 설명을 두 행으로 나눠 좁은 화면의
넘침을 줄인다. 모달은 열린 동안만 내용을 mount하여 상세 폴링·앱 스캔 관심 규칙을 유지한다.
수집기·샘플 간격은 변경하지 않는다. 실제 테마·compact 화면 확인은 여전히 사용자 확인이 필요하다.

## 2026-10-06 · 시각적 정보 구성 (PLAN 5.3절 보완)

사용자가 텍스트 위주 화면의 가독성 개선을 요청했다. `paseo-top` 0.4.3의
`client/pill.tsx` System 탭 및 helper의 Card/ProgressBar/MetricGauge 구성을 참고하여
큰 숫자·카드·사용량 막대·메모리 범례·상위 앱 탭을 직접 구현했다. 레퍼런스 코드는 복사하지 않았다.

React Native 기본 요소로 같은 레이아웃을 구현할 수 있어 추가 UI/차트 라이브러리는 넣지 않는다.
레퍼런스의 웹 conic-gradient 및 사용률 임계값에 따른 상태 색은 승인 계획의 DOM/색 규칙과
맞지 않아 도입하지 않는다. 새 타이머·수집·RPC는 없고 탭 전환은 화면에 받은 목록만 바꾼다.

CPU·물리 메모리·스왑 막대는 전체 값 대비 크기다. 구성 막대는 앱/와이어드/압축이며 캐시는 제외한다.
드물게 구성 합계가 물리 용량을 넘으면 사용량에 맞춰 구성 막대만 정규화하고 화면에 알린다.
앱 메모리 막대는 목록 내 최대 footprint 기준으로 비교하며 물리 RAM 비율로 표현하지 않는다.
누락값은 —와 빈 점선 막대, 이전 값은 지연/오류 표시와 흐린 막대로 구별한다.
상태 색은 OS 압력 배지/점에만 쓴다. compact에서는 주요 카드와 호스트 정보를 세로로 쌓는다.

`test/manual/ui-preview.mjs`는 실제 React 컴포넌트 트리를 HTML로 옮기는 레이아웃 검토 도구다.
출력은 `/tmp/mac-monitor-ui/`에 생성하며 HTML은 클라이언트 번들에 포함하지 않는다.
예시 데이터/예시 테마의 정적 검토이며 실제 Paseo·모바일 화면 검증을 대체하지 않는다.

## 2026-10-06 · 기본 폰트와 스크롤 가능한 상위 10개 (PLAN 1, 2, 5.3절 변경)

사용자 요청으로 모든 client의 `fontSize` 지정을 제거하여 React Native 기본 크기를 사용한다.
큰 수치·장식용 MAC 타일을 제거하고 카드 여백과 모서리도 줄였다. 기본 크기로 제목·수치·각주를
표시하며 범례·막대와 압력 색 규칙은 유지한다.

앱 목록은 CPU·메모리 각각 최대 10개로 늘린다. C 헬퍼 출력 한도, RPC 스키마 한도,
화면 표시를 함께 변경하고 universal prebuilt 바이너리를 다시 빌드·서명한다.
프로세스 스캔·정렬 방식, 2초 주기, 30초 관심 유지 규칙은 변경하지 않는다.
목록 내부는 최대 높이 320의 스크롤 영역으로 제한하고 0.10.2 공식 ScrollView를 사용해

이번 출력 확장 후 다시 측정한 값으로 표현하지 않는다.

## 2026-10-06 · 안내 문구 축소와 앱 목록 높이 고정 (PLAN 5.3절 변경)

사용자가 용량 단위/Activity Monitor/footprint 안내 문구 제거와 로딩 중 높이 변화를 해결하도록 요청했다.
해당 화면 각주를 제거하고 설명은 README에 유지한다. CPU 범위·메모리 합 공식·캐시 제외·압력 색 규칙의
반복 설명도 화면에서 제거했다. 갱신 시각은 헤더에 상대 시각과 시각을 모으고 전체 날짜는 접근성 설명으로 제공한다.
가용 비율·root/권한 제외 수·오류·지연 표시는 유지한다. 앱 메모리 막대의 상대 비교는 짧은 라벨로 구분한다.

앱 ScrollView는 최대 높이 대신 `height: 320`, `flexGrow: 0`, `flexShrink: 0`으로 고정한다.
로딩/빈 목록/미지원 메시지와 실제 목록 모두 같은 영역 안에 렌더한다. 제외 수 역시 목록 내부에 두어
데이터 도착으로 카드 높이가 늘어나지 않는다. 최초 RPC 결과가 없는 때에도 —를 사용하는 같은 카드 구조를
표시하여 첫 로딩에서도 목록 공간을 확보한다. 추가 측정·타이머는 없다.

## 2026-10-06 · pill 툴팁 축소와 수동 갱신·복사 (PLAN 5.3, 5.4절 변경)

사용자가 반복되는 “Mac 시스템 모니터…” 문구와 자동 갱신 중 텍스트 복사 불편을 보고했다.
v0.10.2 호스트의 `plugins/buttons/view.tsx`는 pill의 `button.title`을 툴팁으로 자동 표시한다.
SDK에 툴팁 비활성화 옵션이 없고 `buttons/validation.ts`는 빈 제목도 거절한다.
따라서 긴 안내 제목을 “모니터”로 축소하고 상세 모달 제목도 맞춘다. 툴팁 자체를 제거했다고 표현하지 않는다.

사용자가 자동 갱신 자체가 불편하다고 명확히 요청했다. 상세 모달과 대시보드의 2초 폴링을 제거하고,
열기·호스트 전환·“새로고침” 버튼 때만 읽는다. 포커스·재연결 자동 갱신도 끈다. 다른 창이 같은 Query 캐시를
갱신해도 자기 읽기 결과만 보존하여 수치·앱 순위·시각이 바뀌지 않는다. “고정/재개” 버튼은 제공하지 않는다.
샘플 시각과 “샘플” 배지를 사용하여 수동으로 받은 값을 현재 최신이라고 표현하지 않는다.
서버의 고정 2초 수집과 보이는 pill의 공유 타이머는 유지한다. pill은 요약 지표이며 상세 화면과 별도다.

앱 스캔을 막 켰을 때 첫 CPU 기준점 다음 결과를 받을 수 있도록 읽기에서만 최대 두 번 2.2초 기다린다.
이 초기 대기는 반복 타이머가 아니며 결과 도착 뒤 추가 RPC는 없다. 화면 종료 시 대기를 취소한다.
자동 상세 요청이 사라져 앱 스캔도 마지막 요청 30초 뒤 중단하므로 열린 화면만으로 스캔을 계속하지 않는다.
정보용 Text에는 React Native의 `selectable`을 적용하며 앱 탭 전환과 스크롤은 유지한다.

복사는 0.10.2 공식 `copyText`를 사용한다. 버튼을 누른 시점의 표시 값·샘플 시각·상태·상위 두 목록을
별도 RPC 없이 텍스트로 만들며, 누락값·지연·오류를 보존한다. 클립보드 실패는 성공으로 표시하지 않는다.
반복 타이머·새 측정·DOM 코드는 없다. 자동 갱신이 실제 선택을 끊는 현상과 클라이언트 클립보드의 동작은
실제 Paseo에서 직접 재현하지 못했으므로 사용자 확인이 필요하다.

## 2026-10-06 · 상세 클릭 버블링 수정과 “샘플” 제거 (PLAN 5.3절 보완)

사용자가 “샘플” 표현과 아무 곳을 클릭해도 새로고침되는 문제를 보고했다. “샘플”은 마지막으로 읽은
측정값을 뜻하도록 추가했던 용어지만 UI에는 불필요하다. 정상 상태 배지는 제거하고 측정 시각만 유지한다.
측정 중·지연·오류·미지원 표시는 유지하며 복사 텍스트도 “측정 시각”을 사용한다.

Paseo 0.10.2의 `plugins/buttons/view.tsx`는 action 실행 중 아이콘 대신 spinner를 렌더한다.
`buttons/model.ts`의 `run()`은 모든 action에 pending을 적용한다. 상세 Modal을 아이콘 안에
렌더한 구현에서 웹 portal의 클릭은 React 부모 pill Pressable로 전파되어 action을 다시 실행했다.
그러면 아이콘과 Modal이 unmount/remount되고 상세의 최초 읽기가 반복된다. 이는 폴링과 별개인 결함이다.

Modal 전체를 비포커스 React Native Pressable로 감싸 `onPress`의 `stopPropagation()`으로
이 전파를 차단한다. 내부 탭·복사·새로고침·닫기 동작은 그대로 실행되고 부모 pill은 재실행되지 않는다.
DOM 이벤트 API나 호스트 파일 패치는 사용하지 않는다. SDK 및 프로젝트 의존성도 변경하지 않는다.

`test/manual/click-preview.mjs --verify`는 실제 pill/상세 코드와 Paseo와 같은 React 19.1.0,
React Native Web 0.21.0으로 portal/호스트 pending 동작을 구성해 jsdom에서 실행한다.
전파 차단을 뺀 경로는 본문 클릭 후 action·Modal mount·상세 RPC가 모두 1→2로 증가했다.
수정 경로는 본문·탭·복사·닫기에 action/mount 1을 유지하고 새로고침 버튼만 상세 RPC를 증가시켰다.
브라우저 제어는 사용 불가여서 DOM 실행 테스트로 검증했으며 실제 Paseo/모바일 터치 검증을 대신하지 않는다.

## 2026-10-06 · CPU·메모리 통합 배치와 pill 값 즉시 표시 (PLAN 5.3절 변경)

사용자가 CPU·메모리를 함께 보기 좋게 정리하고 실제 화면을 보며 개선하도록 요청했다.
Paseo 앱에서 기존 사이드바 화면을 직접 관찰했다. 폭 제한 없이 펼쳐지는 카드, 앱마다 반복되는 막대·보조 줄,
정수 반올림 때문에 작은 앱 CPU가 전부 0%로 보이는 점을 확인했다.

CPU·메모리는 한 시스템 카드의 두 행으로 합친다. CPU 막대와 메모리 구성 막대는 유지하고,
압력·가용 비율·캐시·스왑·사용자/시스템 CPU를 같은 카드에 모은다. 앱은 이름·CPU·메모리 세 열로
표시하며 열 제목으로 두 순위 중 하나를 고른다. CPU와 메모리의 수치 또는 순위를 합산하는 점수는 만들지 않는다.
최대 10개와 목록 높이 320은 유지한다. 이름은 한 줄 말줄임으로 숫자 열을 보호하며 전체 이름과 프로세스 수는
접근성 라벨에 남긴다. 앱 CPU만 소수 첫째 자리와 `<0.1%` 표기를 사용한다.
기본 글자 크기·테마 토큰·OS 압력에만 따른 상태 색은 유지한다. 사이드바 내용 폭은 760으로 제한한다.

사용자가 pill이 받은 값을 열자마자 보여 달라고 추가 요청했다. 기존 상세는 앱 CPU 기준점의 최대 두 주기를
기다리는 RPC가 끝나기 전까지 시스템 값도 비워 뒀다. pill은 이미 가진 Snapshot을 Modal에 전달하며,
상세의 로컬 상태를 이 값으로 한 번만 초기화한다. 사이드바도 동일 호스트의 공유 요청 캐시로 초기화한다.
pill이 이후 갱신되어도 열린 상세는 그 값을 구독하지 않는다. 앱 목록을 누락한 요약 Snapshot의 processesStatus가
ok인 경우 UI 초기 상태만 warming으로 바꾸어 빈 목록을 완료로 표시하지 않는다.
초기 앱 결과 읽기와 수동 새로고침·취소는 유지하며 서버 측정 간격과 관심 만료 규칙은 바꾸지 않는다.
추가 라이브러리나 서버/네이티브 변경은 없다.

## 2026-10-06 · 자동 갱신 복원과 화면 간소화 (PLAN 5.3, 5.4절 변경)

사용자가 복사 기능과 제외 통계 제거, 자동 새로고침을 명시적으로 요청했다. 이 지시가 앞선 수동 갱신 결정을 대체한다.

값 갱신은 컴포넌트를 다시 마운트하지 않아 스크롤과 선택한 앱을 유지한다. 본문 클릭 전파 차단도 유지한다.
정상 화면의 복사·새로고침 버튼은 제거하고 RPC 오류 때만 재시도한다. 제외 통계는 수집 데이터에만 남긴다.
pill 값으로 최초 화면을 채우고 이후에는 상세 자신의 자동 읽기 결과로 갱신한다.
서버 2초 측정과 마지막 요청 이후 30초 앱 관심 만료는 그대로다. 추가 라이브러리는 사용하지 않는다.

## 2026-10-06 · 개별 프로세스 종료 (PLAN 1, 2, 3, 4, 5.3절 확장)

사용자는 종료 범위 질문에 “프로세스 목록을 열어 하나씩 종료”를 선택했다. 앱 그룹 전체 종료는 제공하지 않는다.
앱 이름을 눌러 PID별 목록을 열고 대상을 확인한 뒤 SIGTERM을 보낸다. 성공 문구는 종료 완료가 아닌 신호 전송을 뜻한다.
상주 C 헬퍼가 기존 스캔에서 PID·시작 시각·이름을 캐시한다. CPU/메모리 상위 그룹 합집합의 구성원만 서버로 출력하며,
요약 Snapshot에는 포함하지 않고 목록 RPC가 캐시에서 읽는다. 클릭으로 새 스캔이나 별도 헬퍼를 실행하지 않는다.
시작 시각은 uint64 문자열로 전달하여 JavaScript 정밀도 손실을 피한다.
서버는 그룹·PID·시작 시각·신선도를 검사한다. 헬퍼는 현재 사용자 소유·시작 시각을 재검사하고
root·다른 사용자·자신·부모 및 모든 상위 프로세스를 차단한다. 검사 실패는 종료하지 않는다.
강제 종료 및 다른 호스트 집계 행에서의 종료는 제공하지 않는다. 공식 호스트 전환 뒤 해당 설치 RPC만 사용한다.
PID 검사와 kill 사이에는 원자적이지 않은 작은 경합이 남는다. 이 한계와 신호 무시/자동 재시작 가능성을 README에 기록한다.

## 2026-10-06 · SSD 용량 조회 (PLAN 2, 3, 4, 5.3절 확장)

사용자의 SSD 용량 요청에 따라 Data 볼륨 statfs를 단조 시계 기준 30초마다 읽고 결과를 2초 샘플에 포함한다.

파일 트리나 물리 SSD를 스캔하지 않는다. Node 폴백도 같은 API·주기를 사용한다. 실패는 null과 오류로 표현한다.

## 2026-10-06 · 앱 그룹 전체 종료와 좌상단 뒤로가기 (PLAN 2, 5.2, 5.3절 확장)

사용자가 CPU 목록 각 항목의 전체 종료와 앱 진입을 알려 주는 좌상단 뒤로가기를 요청했다.
이는 앞선 개별 종료만 제공하던 범위를 확장하는 명시적 승인이다. CPU·메모리 순위 모두 각 행에 전체 종료를 제공한다.
개별 앱 화면은 시스템 카드 아래 교체가 아닌 별도 상세로 전환하며 맨 위에 ‹ 뒤로와 앱 이름을 표시한다.
뒤로 가면 기존 정렬 기준을 유지한다. 확인/목록 스크롤 영역은 높이 320, 기본 폰트와 테마 색을 유지한다.
compact 화면은 전체 종료 버튼을 다음 줄에 배치해 기존 숫자 열의 폭을 확보한다.

전체 종료를 누르면 목록 RPC로 기존 캐시를 읽고 대상 개수·PID를 확인 화면에 고정한다.
확인 전에는 신호를 보내지 않으며 자동 갱신·새 프로세스 생성이 대상을 늘리지 않는다.
새 RPC mac-monitor.group.terminate는 group과 확인한 pid/start 목록을 받는다. 중복 PID를 거절하며,
서버 캐시·그룹·신선도·시작 시각 중 하나가 불일치하면 전송 전 요청 전체를 거절한다.
목록이 유효하면 기존 단일 헬퍼의 개별 종료 제어를 사용한다. 추가 헬퍼·스캔·셸 명령은 없다.
각 대상은 네이티브 소유자·시작 시각·상위 프로세스 보호를 그대로 통과해야 한다.
일부 거절은 PID별 결과로 표시하며 SIGTERM 전송을 종료 완료로 표현하지 않는다.
실험적 다른 호스트 집계는 계속 조회 전용이다. 같은 이름으로 묶인 CLI의 다른 작업도 포함될 수 있다.

## 2026-10-06 · CPU·메모리 여백 규칙 통일 (PLAN 5.3절 보완)
